# Flow Timer

GitHub Pagesにそのまま公開できる、2モード対応のPWAタイマー。HTML/CSS/JavaScriptのみで動作する。ビルドや外部ライブラリは不要。

## 機能

| モード | 集中 | 休憩 | 集中中の予告音 |
| --- | --- | --- | --- |
| Pomodoro | 25分 | 5分 | 残り10分、残り5分 |
| HFT | 30秒 | 10秒 | 残り15秒 |

- 集中と休憩は自動的に交互に切り替わり、繰り返す。
- **両モードとも、集中・休憩それぞれの残り3秒、2秒、1秒で短い音**を鳴らす。終了時は2音の合図を鳴らす。
- 開始・一時停止・再開・リセット・スキップに対応。開始・再開時にも予告音と同じ効果音を鳴らす。
- **タブを切り替えてもタイマーの状態は変わらない**。新しいモードで「開始する／再開する」を押した瞬間に、もう一方のモードがリセットされる。同時進行はしない。
- ページのタイトルは計測前 `Flow Timer`、計測開始後は `23:45 - Flow Timer` の形式で残り時間を表示する。計測中のモードがあれば、表示タブを切り替えてもそちらの残り時間を使う。
- 終了予定時刻を `localStorage` に保存し、再読み込みや画面復帰後も実時間に応じて復元する。画面を閉じている間も時計上は集中・休憩が自動で進む。
- 効果音はWeb Audio APIで生成するため音声ファイルや外部通信が不要。従来版より音量を引き上げているが、実際の大きさは端末側の音量設定に依存する。
- Pomodoroの集中時はパープル、HFTの集中時はオレンジ、どちらの休憩時もグリーン系のアクセントカラーに変わる。
- Service Workerでオフライン利用に対応。MacやiPhoneでホーム画面・Dockから起動できる。

## GitHub Pagesに公開

1. GitHubで新しいリポジトリ（例：`flow-timer`）を作成する。
2. このZIPを解凍し、`index.html` などのファイルと `icons/` フォルダを**リポジトリのルート**にアップロードする。ZIP自体をアップロードするのではなく、中身をアップロードする。
3. リポジトリの **Settings → Pages** を開く。
4. **Build and deployment → Source: Deploy from a branch**、Branchを `main`、Folderを `/ (root)` にして保存する。
5. 公開URL `https://<ユーザー名>.github.io/<リポジトリ名>/` にアクセスする。

GitHub Pages上のURLがHTTPSであれば、PWAとService Workerを利用できる。パスは相対参照なので、ユーザーサイト（`<ユーザー名>.github.io`）でもプロジェクトサイトでも利用可能。

## Mac / iPhoneで使う

- **Mac**：Safariで公開URLを開き、共有メニューや「ファイル → Dockに追加」で追加する（対応macOS）。通常のブラウザタブでも使用できる。
- **iPhone**：Safariで公開URLを開き、共有メニューから「ホーム画面に追加」を選ぶ。
- 最初にオンラインで1回読み込むと、その後はキャッシュ済みのファイルをオフラインでも開ける。
- 最初に **「試聴」** を押し、音が聞こえることを確認する。音が聞こえなくてもタイマーの計算・表示には影響しない。

## 制約・注意点

- **iPhoneの画面ロック中やバックグラウンドでは、終了音・予告音を保証できない。** PWAやService Workerでも音声再生を継続できるわけではない。通知のプッシュ配信は実装していない。
- 音声再生はブラウザの制約により、最初にユーザー操作（「開始する」や「試聴」）が必要。
- タイマーの復元には端末の時計（`Date.now()`）を使う。端末の時計を手動変更すると終了時刻にも影響する。
- 保存は**端末・ブラウザごと**。MacとiPhone間の同期機能はない。プライベートモードやブラウザのデータ消去で状態が失われる場合がある。
- 新しいモードで開始したとき、もう一方のセット数もリセットされる。タブ切替だけではリセットされない。自分のモードの「リセット」では、そのモードのセット数だけがリセットされる。「スキップ」した集中時間は完了数に加えない。
- 集中・休憩は一度「開始する」を押すと自動でループする。長期間放置して戻った場合、実時間に基づいて進んだセット数を反映する。
- サイト更新後、すでに開いているタブには古いコードが残る場合がある。通常の再読み込みで更新する。`sw.js` の `CACHE_NAME` を変更すると旧キャッシュが消去される。

## ローカル確認

Service Workerのテストには `file://` ではなく、ローカルサーバーを使う。

```bash
python3 -m http.server 8000
```

ブラウザで `http://localhost:8000/` を開く。localhostはService Workerが利用できる安全なオリジンとして扱われる。

## カスタマイズ

- 時間・予告秒数：`app.js` 冒頭の `MODES`
- 色・レイアウト：`styles.css`
- アプリ名とPWAのアイコン：`manifest.webmanifest` と `icons/`
- 静的ファイル変更後のキャッシュ更新：`sw.js` の `CACHE_NAME`
